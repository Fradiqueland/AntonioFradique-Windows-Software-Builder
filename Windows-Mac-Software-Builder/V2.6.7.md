# v2.6.7 — Startup and taskbar icons

The icon already selected in Appearance is now shipped with exported project data and applied to the running Windows window/taskbar and Mac Dock. A persistent, multi-resolution ICO and per-project Windows AppUserModelID prevent grouping under the generic Electron icon. The signed Mac application bundle stays unchanged; its Finder file icon stays the template icon. PNG/JPG work across both hosts; ICO decoding depends on the platform.

Publish now offers a recommended portable ZIP folder and, on Windows with SFX support, a single EXE. Extract the whole ZIP once and keep its files together. Windows ZIP resources use a short-named transport when they contain no symlinks, avoiding legacy ZIP extractor path limits; the Viewer restores them through long-path APIs on first use. Subsequent starts use the prepared folder directly. Mac remains a signed universal .app with a sibling .data folder.

Single Windows EXEs use faster, non-solid LZMA2 packaging and retain validated project resources under the user's AppData cache, indexed by the payload SHA-256. Reopening skips resource hashing and tree extraction when the matching completion receipt exists. Concurrent first starts commit a complete tree atomically; changed payloads get separate trees. The SFX engine itself still extracts each time, so a single EXE is still slower than a prepared folder for large products. No source profile, cache or project file is pruned. If the cache location is unwritable, the Viewer falls back to temporary extraction. Unused asset-cache directories can be deleted while their applications are closed and will be recreated when needed.

Verification includes icon bytes in both ZIP formats, unchanged signed Mac template entries, native Windows HICON pixels, payload integrity and long paths, cache reuse and concurrency, format selection, installed Builder startup, full source/packaged exports and IPTV checks. Filesystem limits remain those of the host operating system.
