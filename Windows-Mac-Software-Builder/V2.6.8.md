# v2.6.8 — Direct single-EXE startup and branded ZIP executables

Windows EXE exports replace the repeated self-extraction stub with a small Win32 launcher built from the included C source using the static MSVC runtime. No external interpreter, emulator, runtime install or administrator permission is required. The first launch validates SHA-256 while streaming its bundled extractor and archive, prepares a private directory, and commits its completion marker atomically. A preparation window is visible only when needed and supports cancellation.

Subsequent launches read the fixed 256-byte bundle footer and small completion markers, then start the retained Viewer directly. They do not scan, copy or decompress the full appended payload. Per-payload directories prevent stale project/version reuse; a mutex coordinates concurrent preparation. Missing critical cached files trigger preparation again. Long project paths still restore through Node's native filesystem APIs. Chromium caches are retained for this prepared application, and a second instance focuses the existing window. The cached runtime is under LocalAppData/WSMB/runtimes and can be recreated from the original EXE.

Windows portable ZIPs contain ProjectName.exe instead of LaunchBox Viewer.exe. The icon selected in Appearance is embedded in that EXE, alongside the product/file description. Pure JavaScript PE resource editing also works in the Mac Builder. Other included executables are not renamed or edited. Mac signed application bundles remain unchanged.

Required validation includes native compilation and a small cold/warm/repair gate, actual exported Viewer windows and taskbar icons, a same-content comparison with the previous SFX, warm-start metrics proving zero payload reads/extractions, native ZIP file icons, Windows exports created on Mac, complete installed Builder startup, source/packaged exports, preserved Mac signatures, long paths, portable imports and IPTV playback. Timing varies with disk, antivirus and machine; first preparation still has to unpack a self-contained application's contents.
